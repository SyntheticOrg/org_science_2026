First test · Exploratory results · 22 October 2026

OpenAI incentive sensitivity

Standalone diagnostics followed by a direct private-cost disclosure pilot. All 32 diagnostic calls and 64 disclosure decisions completed, with no failures or replacements.

Main finding. Both OpenAI models withheld information when its direct private cost exceeded their own bonus, and released it when that cost was reimbursed. The earlier discussion results therefore cannot be explained by a blanket inability to respond to stated private rewards.

The unresolved issue is whether that response carries through to information sharing under strategic interaction. These small, simplified tests do not establish human fidelity or explain the original mismatch causally.

Fixed design and scope

The specification was saved before live execution. Models were gpt-6-luna, the existing baseline, and gpt-5.4-mini-2026-03-17. Both used high reasoning effort, API-default sampling, an 8,192-token output cap, and fresh contexts. Returned model identifiers matched the requested names; the Luna identifier remains an alias.

Each stage crossed two models with the existing payoff-maximising system prompt and the student-participant simulation prompt. There were two calls per cell. No comprehension quiz, corrective feedback, private-note request, or carryover between calls was introduced. The simulation prompt also removes explicit payoff maximisation, so these two wording components remain confounded.

The diagnostics were reviewed before the disclosure stage began. The models, prompts, and planned sample were retained. No calculation aid was added. The fixed pilot uses 96 calls in total; this is separate from every earlier discussion cohort.

For the allocation diagnostic, the private option gave the sender an extra £0, £2, £5, or £13 and gave the others nothing extra. The group option gave each participant £4 extra. Luna selected the group option at £0/£2 and the private option at £5/£13 in every repetition under both prompts.

Mini’s exceptions were specific. In one simulation-framed payment call, it incorrectly awarded the weak-sell bonus to the two unpaid participants when all voted B. In one baseline transcript call, it assigned B strength 7 instead of 4. In one baseline allocation call, it chose a £2 private payment instead of £4 for everyone, yielding a lower own payment. These observations do not identify a single underlying cause.

Payment calculations and applicant scores have objective answer keys. Allocation choices are descriptive behavioral outcomes: a cooperative choice is not scored as a comprehension error. Combining prompt rows here does not estimate a population effect; disaggregated results remain available below.

Stage 2: direct private cost of disclosure

A single LLM participant held a truthful, verified report that B was the best applicant. A fixed software rule selected B if the report was released and A if it was withheld. All three participants received £10, plus £4 each when B was selected. Only the sender bore the disclosure cost. An external budget refunded that cost in the reimbursed condition.

Each entry is the count within each individual model × prompt cell, with two calls per cell. All 64 decisions matched the own-money-maximising benchmark. For every specification, disclosure fell by 100 percentage points between costs £0 and £5 without reimbursement; reimbursing the £5 cost increased disclosure by 100 percentage points. These are tiny-cell descriptive contrasts.

At £5, release paid the sender £9 and each other participant £14; withholding paid everyone £10. The models therefore withheld even though release increased total participant earnings. The marginal trade-off mirrors a successful weak-buy target majority versus a B majority in the original task: £1 more for the paid participant, £4 less for each of the others. The direct-cost task removes uncertainty about how disclosure changes others’ choices, so the two tasks do not identify the same mechanism.

Implication for the research argument

The results distinguish the capacity to respond to explicit private payoffs from its expression in group discussion. Luna showed correct objective calculations and consistent private-payoff sensitivity in these simplified settings. Its earlier cooperative discussion outcomes therefore require a more task-specific explanation than general incentive insensitivity.

Possible explanations include beliefs about the success of persuasion, coordination across incompatible private targets, the indirect return to disclosure, and the conversational interface. The current comparison changes several of these features together, so none is established as the cause. A calculation aid remains a possible later intervention; the new Luna diagnostics do not make it the immediate explanation.

A more precise research-in-progress claim is that valid agentic experimentation requires incentive sensitivity to carry through from individual payoff choices to information sharing under interaction. The evidence here establishes an initial task-dependent contrast, not a replication of the human mechanism. Human benchmarks in the same interface and larger independent samples remain future work.

Future participant models

New checks are restricted to GPT-6 Luna. The completed two-model pilot above is retained as historical evidence. OSim remains a core future human-behavior-model comparator. Centaur is recorded as an alternative to OSim for future testing. Its human-choice training and held-out evaluations motivate considering it; task coverage, interface compatibility, access, and compute still require assessment. Neither OSim nor Centaur was run in this pilot. Qwen is retained only as a historical comparison.

Records, checks, and limits

All 96 planned calls completed, with one HTTP attempt per call. Every request, raw API response, returned model identifier, and token usage is saved. The two stages used the source and design saved before live execution. Stage 2 began after the diagnostic stage finished; no failed call was replaced, no case was selected based on its outcome, and no prompt was revised between stages.

Total usage was 41,144 input tokens and 27,834 output tokens, including 21,631 reasoning tokens. Provider billing was not audited. Eight new local checks passed, including exhaustive payment-rule checks and the saved fake pipeline; all 13 existing harness checks also passed.
